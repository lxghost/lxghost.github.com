十五个生产环境站点，从两页的小工具到多语言文档体系与三本书。 每张卡片都会打开对应的线上站点。

1 - pgsty.com

PGSTY: the company behind Pigsty. A small bilingual corporate site that uses OINK primarily as a data-driven landing-page system.

pgsty.com 是 Pigsty 背后的双语公司站，总共只有十来个 页面：首页使用 type: home，由 data/home/{en,zh}.yaml 组装，其余则是 解决方案、公司信息与价格等聚焦单页。

它展示了什么

  • 几乎不建文档树，也能把 OINK 用作落地页主题。
  • 把紧凑的中英文营销页面作为对等内容维护。
  • 从可复用数据分区搭建首页叙事。

如果项目希望沿用 OINK 的品牌、导航、搜索与多语言约定，但主要需要的是小型 公开站而不是手册，可以采用这一模式。

→ 首页与落地页 · 全部 OINK 案例

2 - pigsty.cc

PIGSTY: the Chinese home of the open-source PostgreSQL distribution. Deployed as an independent single-language site so a very large translation corpus evolves on its own.

pigsty.cc 以简体中文发布 Pigsty。本案例记录的快照有 一千四百九十多个内容文件、三百多篇博客，并拥有独立的数据驱动价格页， 中文也是站点的默认语言。

它展示了什么

  • 把体量很大的双语语料拆成两个独立部署的单语站。
  • 通过替代站点入口与版本菜单连接中英文站。
  • 让每种语言拥有独立的发布节奏与落地页数据。

这一模式牺牲同域语言切换，换来更清晰的维护边界和更小的构建规模。两种语言 都已经是完整产品，而不是零星翻译时，尤其适用。

→ 多语言配置 · pigsty.io 案例

3 - pigsty.io

PIGSTY: the English home of the open-source PostgreSQL distribution. A large site combining a distribution manual, editorial blog, extension catalogue and pricing landing pages.

pigsty.io 是开源 PostgreSQL 发行版 Pigsty 的英文主站。 本案例记录的快照包含一千四百多个 Markdown 文件、两百多篇博客、扩展目录， 以及由数据驱动的价格页面。

它展示了什么

  • 在同一个 Hugo 站点中组织大型文档树与编辑型博客。
  • 把目录内容与结构化数据分开维护。
  • 用 layout: landing 和 data/landing 组装价格页。
  • 用分类法与版本菜单连接同系列站点和历史版本。

当一个英文优先的站点需要同时承载参考手册、动态内容、目录与商业落地页时， 可以采用这一模式。

→ 首页与落地页 · 全部 OINK 案例

4 - silo.pgsty.com

SILO: the community-maintained MinIO fork for S3-compatible object storage. A large bilingual migration whose checked manifest generates the documentation navigation.

silo.pgsty.com 是 S3 兼容对象存储 SILO 的文档站。 本案例快照中每种语言各有四百一十一页。覆盖 387 个上游页面的迁移清单生成 data/docs_nav.json，再由它驱动文档侧栏；站点还提供模块分类法与下载页。

它展示了什么

  • 迁移大型上游手册，同时保留原有信息结构。
  • 从受检查的清单生成导航，避免手工维护整棵目录树。
  • 在导入文档外叠加本地双语内容、分类与下载界面。

当上游语料仍是权威来源，而本地站需要自己的导航、语言对等页和产品界面时， 可以采用这一模式。

→ 导航定制 · 全部 OINK 案例

5 - oink.pgsty.com

OINK: the Hugo theme every site in this library is built with. Public manual, design reference, component gallery and regression fixture in one repository.

oink.pgsty.com 就是你正在阅读的站点。它既是主题的 公开手册，也是真实的回归消费站：组件页面会渲染可运行示例；同一个仓库还 承载设计契约、Book 夹具、下载数据，以及首页和落地页数据。

它展示了什么

  • 文档示例本身就是可执行回归夹具，而不是截图。
  • 一个站点同时服务用户、内容作者、主题开发者与评审者。
  • 组件、Docs、Blog、Book、Case、下载与落地页等界面协同存在。
  • 针对固定的 Hugo Module 依赖检查双语内容。

可以把这个仓库当作完整参考实现；如果新站只需要一两种 OINK 内容模型， 则从更聚焦的案例开始。

→ 组件画廊 · 设计契约 · 全部案例

6 - caps.vonng.com

CapsLock: turn the most useless key on the keyboard into a fifth modifier. A two-page project site whose second page is a data-driven interactive configurator.

caps.vonng.com 是 Capslock 键盘增强方案的 小站，每种语言只有两个页面：首页与交互式配置生成器。生成器读取 data/capslock-v3.json，并在常规文档外壳之外使用自定义 customizer 外壳。

它展示了什么

  • OINK 站点的实用规模下限：小项目无需为一个工具和简介搭建前端应用。
  • 为单个专用交互页面扩展外壳注册表。
  • 把生成器数据与界面、双语说明分开维护。

当文档很少，但一个交互工具仍需要与全站共享导航、主题与语言控制时，可以 采用这一模式。

→ 布局配置 · 全部 OINK 案例

7 - pig.pgsty.com

PIG: the package manager that installs any PostgreSQL extension. A compact bilingual product manual with a data-driven home page and an active companion blog.

pig.pgsty.com 是 PostgreSQL 扩展包管理器 PIG 的 文档站。核心手册刻意保持紧凑——本案例快照中每种语言十八页——同时用五十篇 双语博客承载动态、教程与深入说明，首页则由 data/home 组装。

它展示了什么

  • 为聚焦型命令行产品设计浅层、以单文件为主的文档树。
  • 在不重复设计导航的前提下维护中英文对等页面。
  • 让数据驱动首页与体量更大的博客内容流配合使用。

当参考手册小而稳定，但产品动态、教程与版本背景需要持续增长时，可以采用 这一模式。

→ 文档仓库结构 · 全部 OINK 案例

8 - sow.pgsty.com

SOW: the repository manager that builds and mirrors APT and YUM software repositories. A bilingual operations manual with a download surface fed by release metadata.

sow.pgsty.com 记录 APT 与 YUM 仓库管理器 SOW。 本案例快照中每种语言各有五十五页，并提供独立下载页；版本、标签与发布产物 都由结构化发布数据生成。

它展示了什么

  • 以中等体量维护双语运维文档。
  • 给下载内容独立类型，而不是把链接散落在正文里。
  • 复用发布数据，让软件包元数据只有一个事实来源。

如果软件面向多个平台分发大量产物，并且安装说明、软件源与下载信息需要同步 演进，可以采用这一模式。

→ 发布与下载页 · 全部 OINK 案例

9 - exp.pgsty.com

PG Exporter: the Prometheus metrics exporter for PostgreSQL and Pgbouncer. A bilingual manual combining generated navigation, a structured catalogue and system typography.

exp.pgsty.com 是 PostgreSQL Prometheus 指标采集器 PG Exporter 的文档站。本案例快照中每种语言各十五页，另有三十七篇双语博客； 生成导航、首页数据与结构化指标目录承担了主要的信息组织工作。

它展示了什么

  • 在规模不大但顺序明确的手册中使用 data/docs_nav.json。
  • 从结构化数据渲染领域目录，避免在正文中反复复制。
  • 需要避免请求品牌字体时，选择 typography: system。

当技术产品的参考数据与叙述型文档同样重要，尤其希望字体栈更轻量时，可以 采用这一模式。

→ 字体与品牌 · 全部 OINK 案例

10 - ddia.vonng.com

DDIA: the Chinese edition of Designing Data-Intensive Applications. A multilingual book site and the largest proving ground for OINK numbering, cross-references and indexes.

ddia.vonng.com 以多语言书籍形式发布《设计数据密集型 应用》。本案例快照包含简体与繁体中文各二十四章、第二版英文二十三章，以及 第一版的两套二十一章内容。

它展示了什么

  • 带章节级导航的完整 type: book 阅读外壳。
  • 一百三十多处图、表、公式与示例编号目标。
  • 跨多个版本保持稳定的交叉引用和生成式书籍索引。
  • 在同一出版物中承载多种书面语言变体。

如果长篇内容更看重编号、引用与章节间移动，而不是文档式侧栏，可以采用 这一模式。

→ 创作书籍 · 全部 OINK 案例

11 - tpme.vonng.com

TPME: the Chinese edition of The Product-Minded Engineer. A focused bilingual publication that needs only OINK’s Book shell.

tpme.vonng.com 以中英文发布 The Product-Minded Engineer，本案例快照中每种语言各十八章。它把支持的页面外壳收窄为 [book]。

它展示了什么

  • 只有一种内容模型、完全不需要文档外壳的出版物。
  • 共享视觉与导航体系的双语章节对等页。
  • 比多版本 DDIA 站更精简的 Book 实现。

对于单本教程或译著，这是更清晰的起点：先把站点架构保持精简，再按手稿需要 逐步加入编号与索引。

→ 创作书籍 · DDIA 案例

12 - pgint.vonng.com

PG Internals: the Chinese edition of PostgreSQL Internals. A single-language book site that runs the Book shell on its own, with no documentation tree beside it.

pgint.vonng.com 发布《PG 技术内幕》——Hironobu Suzuki《The Internals of PostgreSQL》的 2018 年中文译稿。站点包含两篇序言、 十一个章节、自动生成的目录，以及一页许可与授权说明，全部为简体中文，没有 英文对等版本。

它展示了什么

  • 一个刻意保持单语的 OINK 站点：只有一棵语言树，语言切换器因为无处可切而 自然让位。
  • Book 外壳承载的是已完成的译稿而非持续演进的手册——章节导航、整书打印输出 与落地页共处一站。
  • 落地页同时署名上游作者与译者，并向持续更新的英文原著给出外链。

当文本已经定稿——完成的译稿或已出版的著作——可以采用这一模式：内容不会再 增长，站点要做的是导览、阅读体验与如实署名，而不是变更管理。

→ 编写书籍 · TPME 案例 · DDIA 案例

13 - pgsql.cc

PGSQL.CC: an operations library for PostgreSQL and the components around it. Several upstream manuals and partially translated language trees share one search and one visual system.

pgsql.cc 把 Patroni、HAProxy、etcd、PgBouncer、pgBackRest 与 pgBadger 的运维手册汇总为一套 PostgreSQL 专题文库。本案例快照中有 二百一十七页英文内容与八十页中文内容。

它展示了什么

  • 为多个上游产品建立一致的本地信息架构。
  • 英文先发布、中文覆盖逐步增长。
  • 不强求翻译完全对等，也能让现有译文及时可用。
  • 用子树在汇编站中保留清晰的产品边界。

当技术文库的来源与翻译成熟度各不相同，但读者需要统一搜索与视觉体系时， 可以采用这一模式。

→ 多语言配置 · 全部 OINK 案例

14 - pgsty.pro

PIGSTY PRO: the enterprise edition of Pigsty. A bilingual documentation and release archive built around reusable, structured release records.

pgsty.pro 用中英文记录 Pigsty v5。本案例快照中，每种 语言各有三百四十三页文档，另有六十七篇双语博客。它最突出的部分是版本档案： 128 个本地化页面通过可复用的 release-card 组件渲染版本数据。

它展示了什么

  • 无需手工维护每张卡片，也能让长期产品历史清晰可查。
  • 在下载页、版本档案与详情页之间共享结构化发布数据。
  • 让文档与编辑型内容保持中英文对等。

如果产品拥有许多在役或历史版本，并且多个页面都要展示一致的发布元数据， 可以采用这一模式。

→ 发布与下载页 · 全部 OINK 案例

15 - ext.pgsty.com

PGEXT: the PostgreSQL extension catalog. 2,241 extensions indexed and 576 packaged, searchable across 16 Linux platforms and 5 major versions.

ext.pgsty.com 是 PostgreSQL 扩展目录：可以按扩展、 包family、依赖，以及每个扩展可用的 PostgreSQL 与操作系统组合进行检索。目录收录 2,241 个扩展，其中 576 个已打包，覆盖 16 个 Linux 平台与 5 个 PG 大版本。

它展示了什么

  • 把可检索的数据集作为站点的主要对象呈现，同时让阅读壳退到一边。
  • 目录与正文共处一个 OINK 站点，这与 PG Exporter 和 pigsty.io 安放结构化数据的方式一致。
